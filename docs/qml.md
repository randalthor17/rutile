# QML foundations (`shell/common/`)

Generated by `tools/gen_qml.py` from `tokens/m3e.json` and `theme/roles.json`
(`make generate`; `make check` fails if they are stale). Never edit these by hand:

| Singleton | Contents |
|---|---|
| `Shapes` | corner radii in px: `none`, `extraSmall` (4) ... `extraExtraLarge` (48), `full` (9999 = pill) |
| `Elevation` | `level0` ... `level5` in px |
| `Motion` | durations `short1` ... `extraLong4` (ms), `easing.*` bezier arrays, `spring(axis, speed)`, `scheme` |
| `Type` | 30 styles (`bodyLarge`, `titleMediumEmphasized`, ...) with size, lineHeight, tracking, weight, font; `family(style)` |
| `Colors` | 49 color roles, `mode`, `load(text)`, `loaded`, `lastError`; built-in fallback palette until the first load |

Hand-written: `Spacing` (Rutile's own 4px scale), `Spring` + `SpringMath.js`,
`PaletteWatcher` (feeds `palette.json` into `Colors`, needs Quickshell).

## Color role names

`on_primary` is `Colors.primaryOn`, `on_surface_variant` is `Colors.surfaceVariantOn`
and so on. QML reads any property named `on` + Capital as a signal handler, so
`Colors.onPrimary` silently returns nothing. The generator refuses such names.
`inverse_on_surface` is `inverseOnSurface` (it does not start with `on`).

## Using the tokens

```qml
Rectangle {
    color: Colors.surfaceContainer
    radius: Shapes.large
}

Behavior on opacity {
    NumberAnimation {
        duration: Motion.medium2
        easing.type: Easing.BezierSpline
        easing.bezierCurve: Motion.easing.standard
    }
}

Text {
    font.family: Type.family(Type.bodyLarge)
    font.pixelSize: Type.bodyLarge.size
    font.weight: Type.bodyLarge.weight
    font.letterSpacing: Type.bodyLarge.tracking
    lineHeight: Type.bodyLarge.lineHeight
    lineHeightMode: Text.FixedHeight
}
```

`tools/lint_hardcoded.py` rejects hex colors and numeric `radius:`/`duration:` in
hand-written QML, so use the singletons.

## Springs

Qt's `SpringAnimation` takes `spring` and `damping` values that are not M3's
stiffness and damping ratio, so Rutile solves the spring exactly instead
(`SpringMath.js`, mass 1, the same model as Compose). A `Spring` is a value that
chases `target`:

```qml
Spring {
    id: press
    target: mouse.pressed ? 1 : 0
    stiffness: Motion.spring("spatial", "fast").stiffness
    dampingRatio: Motion.spring("spatial", "fast").dampingRatio
}
Rectangle { scale: 1 - 0.04 * press.value }
```

Spatial springs (shape, position, size) are underdamped and overshoot slightly;
effects springs (color, opacity) are critically damped and never overshoot.
Retargeting mid-flight keeps the current value and velocity. It is not a
drop-in `Behavior`; a convenience wrapper can come with the component kit.

## Testing without Quickshell

`tools/qtws.py` builds a temp workspace (`shell/common` plus a generated
`qmldir`, because Quickshell normally registers singletons itself), then runs
`tests/qml/tst_*.qml` with `qmltestrunner` offscreen and lints with `qmllint`.
Files importing Quickshell (`PaletteWatcher.qml`) are excluded, so they are only
verified on a real Quickshell session.

Finding Qt: `RUTILE_QT_BIN` (if set, the only place searched), else
`/usr/lib/qt6/bin`, else PATH. Without the tools the Qt checks skip with a message.

QML modules: some installs (nix shells) leave Qt's own QML modules such as
`QtQuick.Window` off the tool's default import path, which makes `TestCase`
fail with `module "QtQuick.Window" is not installed`. `tools/qtws.py` derives the
module directory from the tool's real location (`lib/qt-6/qml`, `lib/qt6/qml`,
...) and passes it explicitly. If that guess is wrong, set `RUTILE_QML_IMPORT`
to the directory that contains `QtQuick/` and `QtTest/`; the failure output
prints the command to do it.

Development uses Qt 6.12 (the nix shell; the flake's Quickshell 0.3.2 is built on it). Qt 6.7 is the minimum
(D31); Qt 6.4, used early in a sandbox, no longer loads the components.

The JS spring math is checked against an independent Python implementation
(`tests/spring_ref.py`), which is itself checked against RK4 numerical
integration.
